# Beta v1.1.4 — Bring your own AI to the canvas

Users describe a diagram and choose a Codex or Claude logo button to open the installed desktop app with a prepared request and temporary canvas access. Their selected model generates workflows, AWS architectures, or combined full-stack diagrams without calling NovaStage's Gemini pipeline or consuming its AI quota. The existing built-in assistant remains available from its own tab.

The desktop flow requires no CLI setup or registered MCP tool. After the user sends the prepared message in the app, its HTTP/shell tools can inspect the canvas, discover tool schemas, search the AWS catalog, read the queued prompt, and propose a diagram through the MCP endpoint. A signed 15-minute capability is bound to that single pending request and becomes invalid after submission or dismissal. Existing persistent MCP configuration remains under Advanced and is not rotated by desktop requests. Users review generated tasks, services, configuration, groups, and connections before appending the diagram. Existing content is preserved. App links prefill a composer and never send a message automatically.

Strict schema limits and catalog/reference validation guard the proposal and acceptance boundaries. Draft acceptance uses one PostgreSQL transaction for every node, checkpoint, parent group, edge, and status change. Duplicate acceptance and removed/banned members are rejected, active generation blocks acceptance, and stale layouts are rebased under a project row lock. A failed write rolls back completely. The shared graph validator also now breaks cycles introduced while reconnecting isolated milestones, improving built-in generation too.

The shared release metadata, package manifest, and lockfile identify Beta v1.1.4, dated October 26, 2026. The Updates tab has four release bullets and preserves prior history.

- Database checks: complete graph persistence, transaction rollback/retry, duplicate acceptance, stale layout rebasing, membership/bans, active generation, and denied browser-role access.
- Browser suite: 24 checks passing, including both app buttons, prepared protocol links, fallback copying, advanced connection setup, prompt queue, content review, acceptance, revocation, keyboard focus, phone layouts and simulated software keyboard. Existing canvas interactions, sharing, and built-in AI generation remain covered.
- Production build and TypeScript passed. Lint is checked over application code and the browser script; unrelated untracked promo directories are outside this release.

These are protocol, database, and isolated browser checks. Native app launches are intercepted in the browser fixture so tests do not create real chats or send messages. Real Codex/Claude account execution still requires the user's desktop test. No production schema or hosting was changed.

## Deployment

Apply `supabase/migrations/023_canvas_mcp.sql` after existing migrations before deploying this release. Existing Supabase service-role configuration is required; no additional AI API key is needed for MCP. See [canvas-mcp.md](../canvas-mcp.md) for the client setup, access model, and deployment details.

Connections use bearer tokens and Streamable HTTP. OAuth-only client installation flows are outside this release. Desktop users need the app installed, review/send the prepared message, and allow any HTTP/shell permission requested by their client. Persistent connector users can configure their clients under Advanced. No further database migration is needed for desktop handoffs. Diagrams are additive; direct overwrites and deletions through external assistants are intentionally unavailable.
