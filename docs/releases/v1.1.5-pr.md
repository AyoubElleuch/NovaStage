# Beta v1.1.5 — Clearer generated diagrams

NovaStage now uses a shared semantic graph and layout contract for built-in AI and external MCP generation. Workflow milestones follow dependency order, with parallel branches and joins; AWS architectures keep their service flow, feedback loops and infrastructure containment. Semantic IDs determine layout before random persistence IDs are assigned, so shuffled equivalent input produces stable placement.

Cards reserve the dimensions used by the renderer. Long titles and checkpoint previews wrap, nested groups grow around their children, headers have reserved space, and orthogonal connections avoid unrelated cards and header bands. Large diagrams fit fully on phones; zoom, pan and details provide closer inspection. External draft review includes a preview built from the same cards and geometry as acceptance, with the selected mode and useful counts.

Validation rejects mode mixtures, duplicate IDs, invalid references, workflow cycles, conflicting containment and unsupported managed-service placement. It does not invent checkpoints, add dependencies, or silently change the meaning of a graph. Workflow and AWS generation each get at most one correction attempt. An unavailable model cannot report a canned diagram as successful generation.

Built-in creation and updates now build and validate the graph in memory before one transactional database write. Retained IDs, completed checkpoints and editing claims survive updates. Version and claim checks reject stale or conflicting edits, failures roll back, and unrelated canvas content remains intact. MCP retains its existing atomic acceptance and duplicate-acceptance protections.

## Validation

- Full Vitest suite, TypeScript and production build are verified before push. Detailed results are recorded in [the rebuild report](../canvas-generation-rebuild.md).
- Geometry and mocked-provider fixtures cover ordering, branches/joins, long content, serverless feedback, nested boundaries, disconnected components, shuffled input, populated-canvas appends and permitted large graphs.
- Real canvas browser fixtures cover desktop and phone, light and dark themes, fit, zoom, pan, details, external draft review and acceptance. Selected [before/after evidence](../canvas-generation-evidence/) is committed for review.
- Database tests execute production migrations in isolated embedded PostgreSQL and check rollback, modes, retained identity, checkpoint completion, claims and stale writes. No paid model quota or real project data is used.

## Deployment

Apply migrations 023–025 if not already installed, followed by **`supabase/migrations/026_atomic_ai_canvas_graph.sql` before deploying 1.1.5**. Migration 026 adds the privileged atomic built-in write function and permits distinct typed connections between the same endpoints. The application fails safely if the required RPC is unavailable. No production migration or hosting change was performed as part of validation.

The shared release metadata, package manifest, lockfile, Updates page, welcome-email labels and application version surfaces identify Beta v1.1.5. Earlier release history is preserved.

## Limits

Routes can still share channels, and dense connection labels can overlap. Cards show bounded previews with full content in details. Updates reflow the affected graph around its anchor instead of retaining every individual manual position; unrelated diagrams stay in place. Existing saved canvases are not automatically rearranged. Native Codex/Claude execution and live model quality require a separate integration check.
