# Beta v1.2.0 — Canvas reliability and faster CI

## PR title

Release beta v1.2.0: improve canvas reliability and streamline CI

## PR description

Improve alignment, editing and recovery while preserving NovaStage's existing visual style. Grid snapping and magnetic guides help align cards and connection ports; controls adapt to drawers and smaller screens. Layout batches save atomically, stale edits are rejected, failed edits remain recoverable, and undo history survives refresh. Built-in AI now requires reviewing a persistent preview before applying changes.

Reduce the core suite from 294 to 194 tests by removing duplicate component and fixture checks while retaining important security, transaction and collaboration coverage. Consolidate CI into three installations, cache builds, cancel superseded runs, and add a separate live staging release gate. Update plan limits, account validation, exports, dependencies, release labels, the five-point update milestone, READMEs and API documentation.

### Validation

- ESLint, TypeScript and the production build pass.
- 194 unit/integration tests pass across 39 files, including real embedded PostgreSQL migration and rollback tests; the final local run took 5.9 seconds versus approximately 36 seconds before consolidation.
- All 54 browser scenarios pass: 26 canvas, 6 usability, 14 reliability and 8 AI checks, plus 20 generated-diagram views. Reliability was rerun after the final recovery-storage warning.
- Production dependency audit: zero vulnerabilities. The full audit still reports 18 development-tooling advisories (6 moderate, 12 high), rooted in glob-matching dependencies. Do not use force fixes that downgrade Next ESLint or change test-tool major versions without a separate compatibility review.
- The consolidated GitHub CI pipeline passed on `be44302`; the final release commit triggers the same checks again. See the PR checks for its result.

### Deployment

Apply migrations **027 and 028**, after existing migrations through 026, before deploying this app. Run the live staging gate with two accounts and verify hosted Realtime, provider responses and production-sized load as described in [operations](../operations.md). The local browser suites use an API model; they do not certify the hosted backend. Hosted migrations and the live staging gate were not run during this implementation.

Recovery is device-local, expires after seven days, and requires the starting graph to match before restoration. AI previews expire after 15 minutes and completed generation consumes quota even when discarded. Acceptance briefly locks graph tables; measure contention on staging before production promotion.
